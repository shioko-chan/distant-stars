# 给 LLM 阅读的配乐乐谱

这里是当前八首配乐的完整音符事件，不是从 MP3 转录的近似结果。
数据直接从 `src/content/music.ts` 展开；每首一个 JSON，`index.json` 是目录。
当前 BCEG 曲目是 `unsent-starlight.json`（《未寄出的星光》）。

## 怎么交给 LLM

只讨论一首时，直接提供对应 JSON，无需提供其余七首。
JSON 里有曲名、说明、分乐器音符、音名、音高、起止时间参数、音量与声像。
《未寄出的星光》另有 `composition`：172 BPM、4/4、B–C–E–G 主动机及段落时间。
其他曲目未补写没有显式记录的拍号或调性；绝对秒数是演奏时间的依据。

可用下面这段提示：

> 请把这个 JSON 当作符号乐谱，先阅读 conventions 和 composition（如有），
> 再分析 parts。每个乐器可能含同时演奏的多个声部，不要把数组理解成单旋律。
> MIDI 数字是音高依据，start_seconds 是绝对起音时间。
> 修改时请用 instrument 和音符 id 指明对象，并说明动机、节奏或和声变化。
> 不要仅凭音符数据声称已经听过音频。

## 音符示例

```json
{"id":"n0002","pitch":"B4","midi":71,"start_seconds":0,"duration_seconds":0.199419,"gain":0.2392,"pan":0.12}
```

- `pitch`：科学音高记法，中央 C 是 **C4 = MIDI 60**；B 是 B 自然音。
  升号拼写只用于显示，不是原作的调性/等音记谱选择。
- `start_seconds`、`duration_seconds`：从曲目开头起算的秒数与音符门限时长。
  时间保留六位小数，最大舍入误差 0.5 微秒；并非整数拍长或五线谱时值。
- `gain`：线性振幅倍率，不是分贝或 MIDI velocity；保留九位小数。
- `pan`：-1 最左，0 居中，+1 最右。
- `phrase`（可选）：同一长笛连奏乐句。句内音符交叉淡化，句末才收气。
- `id`：当前导出内的事件标识，按原始时间顺序编号。后续改谱重新导出后编号可能变化。
- `space`：原混响参数。音符时长不包含全部采样余音、混响和连奏交叠。
- `continuous_pitch`：连续上行 Shepard 声层的规则。该声层的 `midi` 是初始音高，
  不是整段都保持这个音；其余普通音符保持所记音高。

同一 `parts` 下可有和弦、多声部和重叠音符。每条音符单独一行，便于 LLM 查阅、
定位和修改，同时避免把所有字段缩写成难以辨认的数字数组。

## 与实际声音的关系

JSON 保留音符及必要的表现信息，不携带 WAV 采样或合成器完整实现。
要重现现有音色，需要项目里的 `src/presentation/themeMusic.ts`、
`scripts/music/render.mjs` 和 VSCO 原始采样；单独读 JSON 可以分析与改写乐谱。
当前提供导出功能，修改这些 JSON 不会自动修改游戏的 TypeScript 乐谱。

## 重新导出

在项目根目录运行：

```sh
npm run music:export
```

不需要音源或 FFmpeg。导出后脚本会重新解析全部 JSON，逐项核对音符数量、
乐器、音高、时间、增益、声像和连奏标记；`source.sha256` 标识对应的源乐谱版本。
