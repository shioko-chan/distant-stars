# Unreal 渲染迁移验证

验证日期：2026-09-30（Australia/Sydney）。基线：`2291179fbecb1ea0d13bffe74497741ac3ab7e67`。

## 实现范围

`unreal` 分支由 Unreal Engine 5.8.3 绘制居所、城市、猫咪、银河、恒星系和可规划的星球地表。源代码和 npm 依赖已移除 Three.js。React 继续负责管理面板和输入，确定性 Worker 继续持有权威模拟状态；没有把经营模拟改写为 Unreal Tick，也没有更改 v3 存档格式。

居所数据包含 410 个网格批次、276003 个实例和 72 份材质参数。原坐标采用右手 Y 向上，原生端统一转换为左手 Z 向上；三角面顺序随坐标反射转换，避免重复翻转导致背面受光。列车和飞行交通由原生时间表更新实例，猫咪使用导入的骨骼与待机/行走片段。地表程序网格、拾取和模拟共用地理高程。

## 运行验收

通过实际 Unreal 客户端及其内嵌界面执行以下流程，并保存包含原生画面和界面的截图。开发模式和独立 Linux 包均已完成操作验收。

1. 居所加载完成，家具 PBR 与猫咪骨骼材质显示，开始按钮可用。
2. 点击开始，走完入场镜头后进入银河；选择太阳系，再选择地球。
3. 进入地球地表，双击可见陆地靠近；在法国附近绘制道路并批准建设，预算为 113 Cr。
4. 保存、读取，确认 `distant-stars-save-v3` 存在并恢复工程。
5. 返回居所，确认开始按钮重新可用，页面无未捕获 JavaScript 异常。

修正了验收中发现的实例材质用途标记、猫咪 MorphTargets 材质实例标记、纹理 UV 节点、坐标反射、相机曝光和近地表拾取问题。独立包中运行时构建的静态网格还需显式初始化 UV 密度元数据，避免编辑器自动处理掩盖该问题。最终独立包重跑上述流程通过，日志中不再出现网格 UV 断言或缺少材质用途标记。

截图和测试报告生成在被 Git 忽略的 `unreal/Saved/`；打包游戏输出在 `unreal/Packaged/Linux/`。运行方法见 [客户端说明](../../unreal/README.md)。

## 验证边界

- 本次迁移验证 Linux，尚未构建 Windows/macOS，尚未做长期性能与显存压力测试。
- Unreal 原生材质与光照存在视觉差异。旧 GLSL 毛发壳层、太阳辉光、地球大气散射与天空旋转未逐项复刻；导出的城区实例未保留旧渲染器的逐模型距离切换。
- 内嵌浏览器在本机使用软件合成界面，场景由 Unreal 的 Vulkan RHI 绘制。CEF 仍会打印 ANGLE/Vulkan 探测失败日志，已验证其软件界面与交互正常；这不代表网页承担三维渲染。
- v3 存档结构保留，但系统浏览器和 Unreal 浏览器有各自的存储目录，原 `web` 存档不会自动导入。
- 原有 20 km 地理数据精度、经营系统边界和长期平衡性限制继续适用。
