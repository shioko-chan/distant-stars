# 地表规划 0.5：实现与验证

## 实现边界

- 恒星系有稳定的行星 ID、名称、类型、轨道半径、半径和勘测属性。界面可点击或键盘选择行星，既有聚居地关联具体行星。未返回的环境与资源信息不会进入玩家视图。
- 当前每恒星系仍只有一个主要殖民世界。其他行星有独立详情，但尚不能独立殖民；这不是多行星经济模拟的完成版本。
- 球面采用立方体映射和按相机距离细分的四叉树，最少 96 个叶块，最多 11 层。分块边缘使用下垂裙边，颜色按球面方向逐像素生成。近远裁剪距离随高度调整。
- 相机绕同一星球连续移动，滚轮按高度缩放；双击陆地定位。渲染细分不会修改规划坐标。
- 手绘道路与分区笔刷以单位球面坐标保存。道路吸附已批准道路和本地道路草稿的采样节点。当前不是完整道路交叉口拓扑或交通模型。
- 预算在批准命令时扣除；当地机构接收后建立工程。道路、分区消耗当地物资，非保护分区需有已完成 50% 的邻近道路。已完成分区对现有区域经济提供有上限的贡献。
- 批准前可撤销一笔、清空；批准后遵循既有命令延迟。草稿在当前地表组件存活期间保留，已批准项目进入存档、报告和回放。
- 每次 24 项草稿、每世界 96 项已批准开发项目是当前原型容量；地表并未按 12×64 限制玩家绘制范围。既有 12 区人口与经济仍汇总结算。
- 矩形/多边形、已建项目拆除、设施自由放置、道路交叉口、逐车交通、需求驱动的建筑类别和高精度真实地貌未实现。

## 开源参考与取舍

研究入口：

- [Citybound](https://github.com/citybound/citybound)：规划与模拟分离的参考，仓库规划模块采用 Rust；本次没有复制或移植其源码。
- [OpenGlobus](https://github.com/openglobus/openglobus)：球面地形与分层渲染的参考；本次保留既有 Three.js，没有并入另一套完整地理引擎。
- [Cesium 地表绘制说明](https://cesium.com/blog/2016/03/21/drawing-on-the-globe-and-3d-models/)：通过地表拾取获得绘制位置的交互参考。

本次实现使用现有 Three.js / OrbitControls / InstancedMesh 和独立编写的球面规划模块，没有新增依赖。上述参考不等同于已完成源码复用评估。

## 验证

2026-09-16：26 项 Vitest 测试通过。

新增验证覆盖：行星确定性与勘测隔离、非法规划不扣费、预算一致、道路先行、物资不足停工、已建分区经济贡献、远方施工和报告延迟、存档和回放、时间分批一致。地形测试检查三角面朝向、近景细分、远景收回以及对象释放。

浏览器已验证：太阳系行星选择、火星与地球不同详情、进入地表、双击靠近、实际拖动生成道路草稿及报价。

尚未完成浏览器验证：最终裁剪/缩放调整后的视觉回归、道路与分区一起批准后的建筑变化、保存读取后的连续试玩、窄屏与触控。继续浏览器操作时，自动审批因使用额度到达上限而拒绝；没有通过其他途径绕过。模拟层自动化通过不能替代这些视觉与交互验证。
